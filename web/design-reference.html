03 · Controls: use the correct choice pattern

The actual application uses native select elements for compact choices, radio inputs for affinities, and data-driven handlers in its builder modules. A searchable combobox for large equipment catalogs is planned, not integrated.

Button hierarchy

One clear primary action per task area. Use destructive labels and a confirmation step when changes cannot be undone.

Native select + chevron

Chevron centered in reserved right padding; options remain native for keyboard and assistive technology. Do not reintroduce split-button decoration.

Text and number fields

Keep labels outside the field; reserve placeholders for examples, not essential instructions.

06 · Original card rendering, unchanged

This specimen deliberately imports the real bundle loader and SVG renderer. When web/data.json, fonts, templates, and PDF-derived images have been built, it shows a genuine repository card. It never draws a substitute or modifies artwork.

Immutable game material

  • Original 63 × 88 mm SVG artwork and ink splatters are retained.
  • Use renderCardSvg from web/js/templates.js for previews.
  • Never restyle SVG internal classes, stretch card aspect ratio or recolor the print output.
  • Preserve web/js/print.js page imposition, roster rendering and physical A4 layout.
  • Only the screen container surrounding cards may be redesigned.
